# 技术设计

## 边界
Android 宿主新增小型 PlayerController，共用内核模式解析、基本播放控制和单次回退状态。Media3PlayerEngine 与 MpvPlayerEngine 实现相同的 seek/pause/speed/volume 操作；视频 Surface、字幕绘制和平台界面继续沿用现有组件。Go 命令与生成绑定不变。

## 数据流
UiPrefs/显式路由 → 控制器解析实际内核 → 原有 player.play → Go 返回版本、续播位置和地址 → Media3.load 或核心 mpv。

兼容性错误 → 捕获当前 Media3 状态与选中轨道 → 停止媒体输出/手机服务 → await player.stopPlayback → 切实际内核 → Compose 释放旧 Media3 → 原有起播效果以回退版本、位置重新 player.play → 应用状态与轨道。

## 关键契约
- 自动只覆盖现有 Emby 路径，传核心的内核值限定 exo/mpv。
- 仅使用 Media3 已定义的明确错误常量，不按宽泛数值范围、异常文字或无首帧 EOF 猜测。
- 回退续播使用当前实际位置；未准备完成时使用核心解析的 resume_secs。零秒用 from_start=true，非零不保留初始 fromStart。
- 版本使用首次核心返回 media_source_id，避免回退重选。跨内核轨道按媒体身份匹配；无法可靠匹配不随意选第一条。
- 回退前 await stopPlayback，使旧 Started/Stopped 与新 Started 顺序正确；沿用独立的新核心会话。
- 控制器模式按播放目标固定，设置变化只影响后续播放。换目标创建新控制器；同目标重试维持已回退状态。
- 手机通知服务切换到新实际内核；后台服务不持有已释放的旧 Media3。
- 自动模式长按明确选择 mpv；已有手动模式长按仍选择另一内核。
- 手机已有版本/选集面板统一回到页面目标切换：先停止旧输出并等待核心收尾，再更新目标建立控制器；换版本传当前位置，切集不沿用上一集版本或位置。离页清理只随页面退出执行，同页切集不得再触发第二次 stop。
- 起播偏好采用重组时的不可变快照，避免 null-key 协程读到刚更新的偏好后起播、随后的重组又起播一次。页面回归严格核查请求次数、实际内核及 stop/play 顺序。

## 验证与回滚
新增控制器及错误分类测试，复用 Compose 生命周期/TV 与手机测试夹具，测试真实命令顺序和字段。出包不代表真机通过。回滚仅撤本次 Android 实现及规范变更，不迁移数据；存量偏好键兼容。
