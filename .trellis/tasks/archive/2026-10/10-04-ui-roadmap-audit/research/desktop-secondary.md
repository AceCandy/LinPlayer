# 桌面次级页面补充盘点

范围：仅核查本次指定的 Avalonia 页面/组件源码。主线程已确认仓库存在 `.codegraph/`；本记录中的具体结论以工作树代码为依据。未运行应用、构建或测试，未查看截图；“建议”里的渲染项是验证点，不是已复现的视觉缺陷。产品范围按本轮约束理解为 Emby、本地与插件，不据旧文案扩张 SMB/WebDAV 等源类型。

## 覆盖清单

- `AggregatePage.cs`：聚合服务器概览按服务器分卡；加载失败显示建议文案，空列表提示尚未添加服务器；浏览型源提示不提供统计/继续观看；Emby 源显示计数和最多 12 个继续观看卡片的横向滚动条。`AggregatePage.cs:21-43,47-100`。同文件还含 `HistoryPage`：当前服务器/全部筛选、扫描恢复反馈、最近记录排序并最多显示 200 条。`AggregatePage.cs:123-201`。
- `PersonPage.cs`：头像/简介与参演作品并行请求，详情失败保留回退姓名并显示错误，缺简介和空作品有明确状态；作品接口限制 `limit = 60`，失败时整段隐藏。`PersonPage.cs:30-70,73-115,119-150`。
- `RankingPage.cs`：按实际返回分类生成分组 chip 与分类 chip，自动选择首项；加载错误、无凭据/无分类、上游空榜均有状态；前三名独立展示，余项用海报网格。`RankingPage.cs:24-32,62-123,126-160`。
- `CalendarPage.cs`：先展示骨架，再检查本地保存的解锁状态；已解锁后才加载，按当前 Emby 库匹配“可播/已入库”；空日、空表和请求失败均有文案。源码另含 Bangumi/Trakt 选项及付费解锁 UI，属于现存功能描述，不据此扩展本轮支持范围。`CalendarPage.cs:44-105,107-165,170-219,221-245,310-331`。
- `IconLibraryPage.cs`：支持图标名搜索、刷新、上传本地图片、添加/移除用户网络源；区分无内置源与拉取失败；选图后更新当前服务器图标。`IconLibraryPage.cs:25-98,101-177,180-243`。
- `BatchAddPage.cs`：文本/深链先解析并预览，用户再确认添加；明文 HTTP 有警告，统一账号密码仅作为缺省值，部分成功逐项显示结果。`BatchAddPage.cs:20-70,79-117,119-168,170-201`。
- `EpisodeDrawer.cs`：固定宽 420px 贴播放器右侧；按数据生成选集、章节及插件面板标签；分集列表使用 `VirtualizingStackPanel`、上下/Home/End 键导航并尝试滚到当前集。`EpisodeDrawer.cs:26-46,57-105,126-173`。
- `Dialogs.cs`：统一居中模态确认/告知窗，关闭窗口按取消返回；内容区 `MinWidth = 380`，不可调整大小。`Dialogs.cs:18-40,43-80`。
- `Responsive.cs`：内容宽度按 0.05 档缩放，最小系数 0.60；提供卡片/字号缩放与 `Watch`。`Responsive.cs:15-67,112-129`。在所查九个目标文件中未见调用 `Responsive`；全仓现有调用集中在首页、媒体库、详情和轮播等处（`rg` 命中 `LibraryPage.cs:190,376`、`Carousel.cs:60`、`HomePage.cs:619`、`Hero.cs:40,345,757-803`、`DetailPage.cs:128,373-375,523,540,593,755-816,1175-1268,1814`）。

## 具体建议（静态证据；优先级为候选）

1. **高：核实并修正图标库全量建控件/拉图。** 事实：注释称约 1468 格“靠虚拟化面板扛住”，但实际 `ItemsPanel` 是普通 `WrapPanel`；每次 `Render()` 都把所有筛选结果映射为 `Cell` 并立即 `ToList()`，每个格子再启动独立图片请求。`IconLibraryPage.cs:15-23,32-35,170-205`。用户影响：首次打开及每次输入搜索都可能同时创建/请求大量图标，造成 UI 响应、内存和网络负载。静态代码足以证明全量构造；实际卡顿程度仍需在约 1468 条数据和连续输入场景测量。
2. **中：防止日历快速切换来源/筛选时旧响应覆盖新选择。** 事实：来源和“只看我追的”都可在请求期间再次触发 `Load()`；请求成功后无请求代次/当前参数校验，直接把结果写入 `_items` 并渲染。`CalendarPage.cs:49-69,170-194`。用户影响：若请求完成顺序与发出顺序相反，页面可能显示前一来源或筛选的日历。库匹配子请求确有 `ReferenceEquals(items, _items)` 保护，但只约束匹配结果，不约束主日历响应。`CalendarPage.cs:196-219`。需用延迟/乱序响应实测确认可见复现。
3. **中：排行榜错误分支补与成功分支相同的分类过期检查。** 事实：成功返回在渲染前检查 `_curCat != catId`，异常分支则直接写 `_msg.Text`。`RankingPage.cs:126-148`。用户影响：切换分类后，较早发起的旧分类请求若较晚失败，可能用旧错误覆盖当前分类的加载/结果状态。需模拟快速切换并让旧请求最后失败确认。
4. **低：对次级页面做窄内容区/系统缩放渲染抽查。** 事实：目标页未接 `Responsive`；固定尺寸例子包括人物页头像 140×140 且头像与简介横排、图标页搜索框 260 宽和横排操作按钮、批量添加账号/密码框各 200 宽横排、选集栏宽 420、确认框最小宽 380。`PersonPage.cs:40-55`; `IconLibraryPage.cs:30,77-96`; `BatchAddPage.cs:23-30,56-66`; `EpisodeDrawer.cs:28,39`; `Dialogs.cs:51-70`。用户影响：小窗口或较大系统缩放时可能挤压/遮挡内容；源码静态尺寸不能证明实际溢出。建议在应用支持的最窄窗口与常用缩放档检查这些入口的可见性、焦点和滚动。
5. **低：确认人物作品上限及失败反馈是否符合预期。** 事实：人物作品请求固定 `limit = 60`，空数组显示“没有找到参演作品”，异常则直接返回，隐藏标题/错误状态。`PersonPage.cs:119-150`。用户影响：超过 60 项的作品是否可继续浏览、接口失败是否会被误认为没有作品，代码本身无法判断产品预期；需用大作品集和失败注入核实需求与当前反馈，不把它直接判为缺陷。
