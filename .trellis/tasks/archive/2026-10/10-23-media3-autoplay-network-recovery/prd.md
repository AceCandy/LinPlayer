# 修复手机 Media3 网络恢复后连播持续加载

## 目标

修复 Android 手机普通 Media3 播放在网络卡顿并恢复后，后续每次自动连播持续出现短暂加载、必须退出播放页重进才能恢复的问题。用户无需重建播放会话即可恢复正常连播准备。

## 用户确认的现象

- 平台是 Android 手机，内核为 Media3，非流影。
- 初次进入播放后，自动连播可以没有加载转圈。
- 播放期间网络卡顿一次后，即使网络恢复，后续每集衔接仍短暂转圈。
- 退回详情页再进入，后续连播恢复到不转圈。
- 用户已同意创建排查修复任务，并在规划审阅后批准实施。

## 要求

| 编号 | 要求 |
|---|---|
| R1 | 查清当前播放会话在网络卡顿后的预载、取消、恢复与队列接管状态，修复可复现的根因，不将相关现象直接归因为网络或内核缺陷。 |
| R2 | 网络恢复且数据、当前集缓冲与下一集准备条件满足后，在原播放页内恢复后续连播准备，无需退出重进。 |
| R3 | 保留真实等待、失败反馈与正常起播降级；不得仅隐藏加载动画、延迟提示或提前假报就绪来宣称修复。 |
| R4 | 保留季内顺序、停止屏障、实际条目身份、续播、字幕和手选轨道、音量、倍速与播放上报，不重复停止或起播。 |
| R5 | 仅修改被证据证明相关的普通手机播放路径。流影、MPV、TV、桌面和服务端不在主动改动范围；若共享底层确须修改，先核查影响并更新方案。 |
| R6 | 不自动编译安装包、安装应用、提交或推送。测试仅执行针对性回归；设备可用性及真实播放验收单独报告。 |

## 验收标准

| 编号 | 对应要求 | 可观察结果 |
|---|---|---|
| AC1 | R1/R2 | 故障注入覆盖正常连播、播放中卡顿、恢复网络、原播放页连续至少三次自动换集；回归在原故障机制下失败，修复后通过。 |
| AC2 | R2/R3 | 在预载能够完成的受控条件下，后续集重新完成媒体准备并由队列接续，不持续退回停止后重新起播；真实缓冲仍显示提示。 |
| AC3 | R3/R4 | 准备失败或未就绪仍可正常起播，无无限重试、重复播放/停止或错误消费旧请求；退出和迟到回调不会污染新会话。 |
| AC4 | R4/R5 | 相关连播、预载、生命周期与上报回归保持通过；独立复核真实 diff 和共享调用者。 |
| AC5 | R6 | 明确区分静态推导、自动回归、真实网络复现及设备播放；未完成的设备验收不得写成已修复证明。 |

## 范围外

- 不重写普通播放器，不迁移到流影双播放器方案，不新增配置或第三方依赖。
- 不承诺任意网络、片源及编码组合下视频首帧绝对无间隙。
- 不修改用户数据、缓存容量、服务端接口、季末行为或现有内核选择。

## 技术证据边界

- `apps/android/app/src/main/kotlin/xyz/linplayer/app/ui/player/PlayerPage.kt:543` 在缓冲许可变化时取消或重新创建 Media3 预载源。
- `apps/android/app/src/main/kotlin/xyz/linplayer/app/ui/player/ExoPreload.kt:93` 对相同 pending 条目直接返回，当前没有完成/失败监听。
- `apps/android/app/src/main/kotlin/xyz/linplayer/app/ui/player/PlayerPage.kt:561` 的排队单次尝试按 controller 重置，不能单独证明跨多集持续异常。
- 这些是排查入口，不是已经确定的根因；最终实现以可重复故障和回归证据为准。
