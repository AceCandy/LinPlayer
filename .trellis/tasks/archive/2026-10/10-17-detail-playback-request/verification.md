# 验证与复核

## 修改
- prefs.preloadItem 可选 return_media 模式：单次带 DeviceProfile 的 PlaybackInfo 生成版本数组与后台预热目标；旧命令即时状态模式不变。
- 预热关闭也返回版本；请求错误透传。媒体响应只属于本次调用，不保存全局缓存，正式 ResolveStream 继续新请求。
- 手机合并版本/预热两路请求；桌面可播详情合并，页面内 Task 共用防止重绘重复出网，失败可重试。TV未存在同类双请求组合，未修改。
- 旧核心返回预热状态对象时，两端回退旧 emby.itemMedia。

## 已验证
- 新命令回归在修改前失败（返回状态对象而非版本数组），修改后通过。

- 覆盖关闭预热、偏好选版、请求失败、请求/离页/正式播放/新详情取消，以及媒体返回不等待视频探测、随后取消后台探测。
- go test -race ./emby ./player ./net/preload ./net/prefetch -count=1 全部通过。使用项目工具链；LD_LIBRARY_PATH 指向现有本地 mpv-test 库。未指定该路径的首次测试两项 mpv 初始化失败，补齐环境后通过。
- go vet ./emby ./player 通过。
- Android参数/响应字段检查、绑定生成一致性、git diff --check 通过。
- Desktop dotnet build --no-restore 通过（21项现存依赖/可空性等警告，未新增依赖）。
- Android首次更新测试缺少JsonPrimitive导入，已修复；原60项详情测试通过。新增旧核心兼容测试后增量缓存冲突，关闭增量编译并使用in-process编译重跑，最终61项详情测试全部通过（37+24）。

## 独立复核
- 核心与宿主分开只读审查，最终兼容分支与桌面请求复用再次审查。
- “旧defer cancel会取消新ctx”不成立：cancel是每次调用的局部闭包，并非读取全局warmCancel。
- 补充响应返回后视频探测取消测试；桌面避免以提前置位的bool代替完成后的UI渲染，改为页面内共用请求Task。
- 页面实例绑定构造时item与session，未建立跨账号/跨条目的共用缓存。

## 未验证与边界
