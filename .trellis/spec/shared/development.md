# 开发与安全纪律

## 开工与修改范围

- 面向用户用中文；命名使用英文，注释写业务意图和约束。
- 先确认上下文、假设与多种解释；多步骤任务给出简短计划和可验证目标。
- 优先完整实现核心目标，再比较后续风险、可维护性。遇到影响正确性、行为、数据、安全、兼容性或不可逆操作的冲突，先澄清并等待批准。
- 仅修改必要内容，匹配附近风格；保留原有注释解释的约束。不清理无关代码，不增加未请求的功能、配置或单实现抽象。
- 有 `.codegraph/` 时先用 CodeGraph 理解符号与调用链，真实修改以工作树为准；文字检索用 `rg`，不全量扫描依赖或构建目录。参见 [CodeGraph 入口](../../../CODEGRAPH.md)。
- 已知小文件直接读取；宽范围探索或独立核验可委派。修改与最终判断由主线程负责，结果按出处抽查，不重复通读已委派材料。

## 错误与注释

- 用户可见错误使用中文；不为无法发生的路径加兜底。允许静默的错误必须说明原因。
- 注释写结论和约束，过程进入 lessons；桌面机器可查风格见 [桌面规范](../frontend/desktop.md)。
- 不写假入口、假成功或“以后接上”的占位实现；判断能力先看命令表、调用方与真实实现。

## 验证与交付

- 新回归测试或门禁须在真实故障/忠实故障注入下失败，再在修复后通过。
- 修复同类问题要检查共享调用者、上下游和各入口；不得把未验证的归因当结论。
- 实现与审查分离，完成后独立复核；布局、焦点、层叠和视频显示需要实际渲染，编译不代替验收。
- 核查命令和交付路径见 [构建与交付](build-release.md)；失败门禁解决根因，不跳过 hook。
- 用户要求整体交付时全量闭环后再交；报告改了什么、验证了什么、没有验证什么与剩余风险。
- Java 修改默认不执行全量编译；需要编译/测试时先说明原因并等待用户批准。此约束不自动扩展为 Kotlin / C# / Go 的禁止测试规则。

## 隐私与仓库卫生

- 真实地址、端口、线路、账号、密码、密钥与 token 不进入代码、注释、日志、文档、示例或提交说明；配置值存放在忽略的 `.env`、`*.local` 等文件，只提交无敏感值的模板。
- 公开资产豁免仅认 `scripts/secrets-allow.txt` 中的具体条目；新增豁免先确认。存量基线不授权新增敏感内容。
- 不在注释、提交说明或作者信息中写工具或模型名称。
- 只逐个文件 `git add`，禁用 `git add -A`；未获用户提交指令不提交。获准提交 / 推送后默认直接使用 main，不开分支或 PR，除非用户另有要求；采用既有中文提交风格，不超出提交 / 推送授权，也不擅自改写历史或删库。
- Bash 中的提交说明不用 PowerShell here-string；大文档使用文件写入工具，避免 shell 吞引号。
- 删除/覆盖前看目标；可拉取的库删除前先确认 CI 有 fetch。缓存、密钥、运行数据与构建产物须被忽略。
- 结束前关闭本次启动的调试服务，删除新产生的临时日志、导出与隐私文件；需保留的本地产物确认忽略规则。
