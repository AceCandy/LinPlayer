# 跨层数据流检查

适用 Emby handler → Go 功能包 → commands / bus → FFI / 事件泵 → 宿主状态 → UI 的变化。

## 修改前

- 画清实际输入、转换、持久化和显示链路；写出每段拥有者。
- 核对命令名、HTTP 方法、分页、字段 / 空值、错误与重试语义；不能靠一般 Emby 知识补齐当前服务端行为。
- UI 是否经过会话合并入口？取消令牌、路由和账号代次是否沿链路传递？
- C 字符串、事件消费者、视频 surface 与进程资源的所有权由谁承担？
- 旧响应完成、离页或换账号时，谁防止它写回失效状态？

## 修改后

- 断言实际命令参数、结果字段与错误码；编译无法证明字符串接线正确。
- 检查字段往返与未知配置键保留，不能因新字段覆盖旧数据。
- 核查各端调用者，避免同一核心规则被宿主重复实现。
- 根据改动跑契约回归、真实联调与 UI 渲染；明确每项证据的适用环境。
